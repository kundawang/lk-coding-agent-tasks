我们项目文案散在代码和 html 里，上多语言的时候全靠人肉 grep，漏一个线上就是一堆中文。
想让你做个文案提取 + i18n 校验的工具。

样例我放在 samples 里了：src 下是源码，locales 下是中英文词条（英文那份故意留了问题），
格式 README 里有，别改。

要做两件事：

一是提取：把源码里要翻译的东西挑出来——`t('key')` 这种调用、html 上的 `data-i18n` 属性、
还有代码里直接写的中文串。中文串要顺手给我一个建议 key，按 README 里的命名规则来。
提取出来的列表要能导出（JSON 或那种一段一段的文本都行）。

二是查错，这几类必须报：

- 源码用了、词条里没有的 key
- 词条里有、源码里没人用的（这种最容易越攒越多）
- 中英文两份 key 对不上的
- 词条值是空的、或者英文那份里还留着中文

每条要能告诉我是哪个文件、第几行，点一下跳过去。

还要能看出来"这次改了之后跟上次比多了/少了哪些 key"，我不想每次都得自己对着看。

别引库、别 npm、别构建，原生 ES module。README 里写清楚提取规则、命名规则、各类问题怎么判的。
