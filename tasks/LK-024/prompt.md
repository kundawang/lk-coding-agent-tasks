我们运维群里老有人把 cron 写错，`0 3 * * *` 和 `0 0 3 * * *` 混着用，写错了要等第二天才发现。
想让你做个网页工具：粘一个表达式进去，立刻告诉我它下次什么时候跑。

样例表达式和一份验算表在 samples 里，格式 README 里有，别改。

要做的：

把表达式解析出来，用人话解释一遍（"每天 3 点整"这种），然后列出接下来 10 次的运行时间。
要支持 `*`、区间 `9-18`、列举 `1,15`、步长 `*/15` 和 `0-30/5`、`?`、
还有 `JAN`/`MON` 这种名字，以及 `@daily`、`@hourly` 这些别名。

几个容易踩的地方，我要你特别照顾好：

- 时区：我可以选时区（默认 Asia/Shanghai），换个时区结果要跟着变
- 夏令时：选一个会切夏令时的时区（比如 America/New_York），
  春天少的那一小时、秋天多的那一小时，都要给出说得通的答案，不能算出一个不存在的时间还装作没事
- 日和周同时指定：这个在 cron 里是有讲究的（不是简单取交集），你要按标准来，并把规则写进 README
- 非法表达式（`99 0 * * *`、字段数不对、`2 月 30 号`）要明确说错在哪，别给个空结果

还要能反过来用：给我一个时间点，告诉我"哪些表达式会在这一刻跑"。

别引库、别 npm、别构建，原生 ES module，别调任何在线服务。README 里写清楚支持哪些写法、DST 怎么处理的。
