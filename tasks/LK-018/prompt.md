我们订单状态机是被几个人陆续改出来的，现在谁也不敢动——上个月有人加了个状态，结果那个状态永远进不去；
还有个状态进去就出不来，生产上卡了一批单子。

我把现在这份导出成 JSON 放在 samples/machine.json 了，格式 README 里有，别改，里面**故意留了几个问题**。

想要的：

左边画布上画状态和转移（状态是圆角框，转移是带箭头的线，线上写事件名），能拖着挪位置、
能新建状态、拉线建转移、改名字和事件。右边是检查结果列表。

检查要真做出来，不能只画不查：

- 从初始状态**不可达**的状态
- 非终止状态里**出不去**的（死锁）
- 同一个状态下**同名事件指向了两个不同的目标**（这种最坑，行为不确定）
- 转移里**引用了不存在的状态**

每条问题点一下，画布上对应的状态或连线要跟着高亮，我要能直接跳过去改。

还有：

- 导出要能再导回来（同一份 JSON 结构），别导出个只有你自己能读的东西
- 撤销要能用，至少 50 步
- 布局别全靠手摆，给个"自动排一下"的按钮，至少别让线叠成一团
- 画布能缩放和平移，状态多了要能看全

别引库、别 npm、别构建，原生 ES module + Canvas 或 SVG 都行。README 里写清楚怎么开、
JSON 格式、四类检查各是怎么判的。
