我们要测接口和页面，每次都得手写一堆假数据，写完还不一致——上次同一条用例跑两遍，
出来的用户列表都不一样，根本没法复现 bug。想让你做个测试数据生成器。

生成规格我写在 samples/spec.json 了，格式 README 里有，别改。

要做的：照规格里的表和字段造数据，一张表几百上千行，然后导出成 JSONL 和 SQL INSERT 两种格式。
字段类型我列在 README 里了：自增序号、姓名、邮箱、枚举（带权重）、整数、浮点、布尔、日期、外键引用。

三条我特别在意的：

一是同一个种子必须一模一样。种子加规格不变，今天生成和明天生成、我这台机器和同事那台，
导出的内容要逐字节相同。所以别用 Math.random，要有自己的随机源，而且生成的先后顺序也得稳定。

二是约束要真生效。标了 unique 的邮箱不能出重复；外键要指向真实存在的行；
权重是要影响分布的（写 [5,3,2] 就该是 5:3:2 那个比例，别写成平均）。
这些我要能看到验证结果，不是你说生效就生效。

三是约束冲突要说清楚。比如只让生成 500 行，却要求 600 个不重复邮箱——这种情况必须明确报错并告诉我
最多能给多少，绝对不能悄悄塞重复值糊过去。

界面上给我种子、行数、每张表的实时预览（前 20 行就行），改完立刻能看到新结果。

别引库、别 npm、别构建，原生 ES module。README 里写清楚随机源怎么设计的、各字段类型怎么生成、
约束冲突是怎么检测的。
