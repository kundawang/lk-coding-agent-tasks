我们对外文档老是被挑毛病：同一个东西一会儿写 master 一会儿写主节点，一会儿 k8s 一会儿 Kubernetes，
还有中英文挤在一起没空格、全角半角混着来。想让你做个检查工具。

术语表和一段故意写错的文档在 samples 里，格式 README 里有，别改。

做法就是：把文档贴进来，跑一遍，右边列出所有问题。每条要告诉我是第几行、原文长什么样、
建议改成什么。点一条能跳到正文对应位置并高亮。

要查的东西我列在 README 里了，重点这几类：术语误用（包括大小写，比如 sqlite 要写成 SQLite）、
中英文之间缺空格、全角半角混用、重复词（"的的"、"the the"）、英文拼写。

两个我比较在意的地方：

一是别乱报。专业名词、变量名、代码片段里的东西不能当成拼写错误；术语表里 ignoreWords 那些直接跳过。
误报太多我就不想用了，所以宁可不报也别瞎报。

二是要能改回去。检查完给我一份"一键替换"的结果，替换掉的那些要做成可撤销的，
别一股脑改完我找不回来。

顺带能导入一份自己的术语表（格式一样），不用每次改代码。

别引库、别 npm、别构建，原生 ES module。README 里写清楚每类检查的判据、误报是怎么避免的。
