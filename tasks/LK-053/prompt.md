我们项目里用 isort 管 import 排序，pre-commit 里给这个仓库配了 --interactive，改之前先让人确认一下。

有个同事在 Git Bash 里跑 `isort . --interactive`，敲完直接就崩了，抛出来的是 EOFError，
错误信息里还让我们去上游提 issue。同一条命令在 cmd.exe 里跑没事，写成
`isort . --interactive | tee isort.log` 也没事，就只有那个终端会崩。我们自己猜是那种终端里
标准输入被当成关掉了，读不到东西。

我们要的效果是：交互那一步读不到输入（输入被关掉、没有内容可读）的时候不要直接崩，
当成用户选了退出，退之前给一句人看得懂的提示，别甩一坨堆栈出来；能正常读到输入的时候，
原来 y / n / q 怎么走现在还怎么走，别改行为。

顺便把这种情况的测试补上，别的别乱动，命令行参数和对外接口都保持原样。
