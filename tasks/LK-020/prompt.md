我们交付前要自查可访问性，现在靠人肉看，漏得厉害。想让你做个网页版的审计面板：
贴一段 HTML（或者直接打开我们那张样例页），跑一遍规则，给我一份能照着改的报告。

样例页和规则清单在 samples 里（page.html、rules.json），规则的含义 README 里有，别改这两个文件。

想要的：

左边是页面预览（在沙箱里渲染，别让它的脚本乱跑），右边是问题列表，按规则分组。
点一条问题，预览里对应的元素要能高亮出来——我要能直接看到是哪一行的问题，不然还得自己找。

要实现的规则（README 里那份清单，enabled 为 false 的跳过）：

- 图片没有 alt
- 表单控件没有关联的 label
- 文字和背景的对比度不够（阈值从 rules.json 里取）——颜色可能是十六进制、rgb()、或者带在样式里的，
  这部分要自己算，别只认一种写法
- 标题层级跳级（h1 直接到 h4）
- 用了正的 tabindex
- 重复的 id
- 链接没有可读文字（空的，或者只有"点这里"这种）

每条问题要说清楚：命中哪条规则、是哪个元素（选择器或者路径）、为什么算问题。

两个要求：

一是别误报也别漏报。白色背景配浅灰字那种要报出来；对比度刚好卡在阈值上的要按规则算准
（阈值 4.5 就是 4.5，不能四舍五入糊过去）。同一个页面跑两遍结果必须一样。

二是报告能导出，JSON 和 Markdown 都要，别人看了能照着改。

别引库、别 npm、别构建，原生 ES module。README 里写清楚对照度是怎么算的（WCAG 那条公式）、
规则是怎么遍历 DOM 的。
