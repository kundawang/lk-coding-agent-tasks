我们日志里时间都是各时区的，之前排一个跨国的线上问题，被夏令时坑了一整天——
有个时间点在新泽西是不存在的，我们的人还在那儿算。想让你做个转换工具。

时区规则和一组用例在 samples 里，格式 README 里有，别改。

要做的：左边选源时区、右边选目标时区，输入一个本地时间，给出转换结果；
也要能反过来（给时间戳算各地的本地时间）。

两个重点：

一是夏令时边界。春天往前跳的那一小时（比如 02:00 到 03:00 之间）在本地时间上是不存在的，
秋天往回调的那一小时是有歧义的（同一个本地时间对应两个时刻）。
这两种情况必须明确指出，不能算出一个不存在的时间还告诉我一切正常。

二是双向要能互推。本地时间转成时间戳、再转回来，必须一模一样，
跨日期、跨年、闰年 2 月 29 号都不能错。

用例文件里每条都要跑出和 expect 一致的结果。

界面再加一个"同一时刻的世界时钟"视图，横着排几个城市，我要一眼看出谁在第二天。

注意：时区规则就按 samples/zones.json 里的来，别引任何时区库，也别调在线接口，
规则自己算。README 里写清楚夏令时起止怎么判的、不存在和有歧义的时间各是怎么处理的。
