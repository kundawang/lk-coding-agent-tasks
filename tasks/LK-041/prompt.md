我们要给内部票据印二维码，但不想依赖在线服务也不想引库——怕哪天接口挂了、也怕数据出去。
想让你自己按标准实现一个。

要编码的内容在 samples/payloads.json，含中文和卡边界的长度，格式 README 里有，别改。

范围就是 Model 2 二维码、纠错等级 L/M/Q/H、字节模式（UTF-8）、版本 1 到 10。
内容超出容量要明确说"需要更高版本"，别默默截断。

得自己实现这几块：数据编码和分块、GF(256) 上的 RS 纠错、按标准评分挑最优掩码、
格式信息和版本信息的 BCH 编码，最后画成矩阵。

两个重点：

一是得能解回来。你写完编码器之后，再写一个解码器，把生成的矩阵读回原始内容，
两边对上才算真的对。我只接受"自己能解出来"的验证方式。

二是结果要确定。同一份内容、同一个纠错等级，生成两次结果必须完全一样（掩码评分不能让随机性影响）。

最终的验收是拿手机扫——扫不出来就不算完成。中文、空内容、超长内容都要能扫。

别引库、别 npm、别构建，原生 ES module。README 里写清楚支持的版本与纠错等级、
掩码评分怎么算的、编解码怎么互相验证的。
