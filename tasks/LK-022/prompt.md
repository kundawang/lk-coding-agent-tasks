同事发我的补丁（git diff 那种）我经常打不上去，报错就一句 "patch failed"，我根本不知道是哪一段对不上。
想让你做个网页版的补丁应用器。

要改的文件和一个补丁我放在 samples 里了，格式说明 README 里有，别改。

流程就是：把文件和补丁放一起，点应用，然后给我一份结果。我要看到——

哪个文件成功了、哪个失败了、失败的具体是哪个 hunk、在第几行、期望的上下文长什么样、实际读到的是什么。
光说"失败"没用，我得能照着改。

补丁里有些情况你都得照顾到：新增文件、删文件、重命名、hunk 上下文对不上（文件被人改过）、
文件压根不存在、还有文件最后一行没有换行符那种。

上下文对不上的时候，别直接报错就完了——我希望能选"尽量打"：能在附近找到相似上下文就贴上去，
同时明确告诉我"这里是模糊匹配的"。找不到就老实失败。

动手之前先给我一个 dry-run 预览：哪些能打、哪些打不上，我确认了再真的改。改完的文本要能下载。

别引库、别 npm、别构建，原生 ES module。README 里写清楚匹配规则、模糊匹配的判据、dry-run 报告怎么看。
