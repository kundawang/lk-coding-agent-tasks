我们想批量改一些老代码，但现在只能靠全局搜字符串替换，一不留神就把字符串里的名字也改了。
想让你做个按语法结构找代码的工具。

源码和几条搜索模式、重命名任务都在 samples 里，格式 README 里有，别改。

要做两件事：

一是结构搜索。我写 `console.log($x)` 这种模式（`$x` 是通配），你要把代码解析成语法树再匹配，
不是拿文本去比。匹配结果要列出来：哪个文件、第几行、匹配到的那段代码长什么样。
同一个标识符出现在字符串或注释里，不能被当成匹配。

二是重命名。我指定把 `calcTotal` 改成 `computeTotal`，范围是整个项目或单个文件。
改之前先给我一条条 diff 预览，我能勾选哪些应用、哪些不要。名字被当成对象属性用
（`obj.calcTotal`）的时候要不要一起改，你按 scope 规则定，但要写进 README 说清楚。

这个解析器得自己写——不许引现成的 JS 解析库，也不许用 eval。
语法子集我列在 README 里了（变量声明、函数、调用、成员访问、字面量、if/for/while、import/export）。

解析不了的语法（比如用了我们没覆盖的写法）不能崩，要跳过并告诉我哪个文件哪一行没解析成功。

别引库、别 npm、别构建，原生 ES module。README 里写清楚语法子集、模式匹配规则、重命名的作用域规则。
