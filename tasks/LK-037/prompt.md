我们的目录树有两三千个节点，现在用递归组件渲染，展开全部就卡死了，拖拽更是没法用。
想让你做个能扛住的树编辑器。

一棵树放在 samples/tree.json，格式 README 里有，别改。

要做的：展开折叠、选中、就地重命名（回车确认 Esc 取消）、增删节点（删有子节点的要二次确认）、
键盘上下左右移动和 F2/Delete，还有拖拽换父级——拖到节点上变成子节点、拖到两个节点之间变成兄弟节点。

三个重点：

一是性能。三千节点展开全部之后滚动、折叠、拖拽都要顺，该虚拟化就虚拟化，
界面上给我看看当前渲染了多少个节点。

二是拖拽不能出环。把一个节点拖到自己后代下面必须拒绝并提示，不能让它悄悄变成一个环，
然后整个树渲染的时候炸掉。

三是导入坏数据要能定位。samples 里那棵树是好的，但我要能导入"重复 id""file 类型还带 children"
这种坏数据，你得报出具体是哪个节点有问题，而不是整份加载失败。

撤销重做至少 50 步，改名、删除、拖拽都要能退回去。

别引库、别 npm、别构建，原生 ES module。README 里写清楚虚拟化怎么做的、环检测怎么判的、坏数据怎么定位的。
