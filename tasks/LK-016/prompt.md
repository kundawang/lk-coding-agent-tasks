我们设备上报的文件是二进制，出了问题同事只能拿十六进制编辑器硬看，很痛苦。想让你做个网页版的解析工具。

两个样例我放在 samples 里了：sample.png 是一张真 png，record.bin 是我们自己的一种记录格式，
格式定义在 README 里，别改这两个文件。

想要的：

把文件拖进页面，左半边是十六进制视图（带偏移、ASCII 那一列），右半边是按格式解出来的结构树。
点结构树里的任意一条，左边要跳到对应的字节并高亮——这一条是我最想要的，不然还是得自己数。
反过来鼠标划过十六进制里的字节，也应该能提示它属于哪一段。

要认的格式：

- png：签名 + 一串 chunk，长度、类型、数据、校验都得大端解析。IHDR 要把宽高、位深、颜色类型解出来，
  IDAT 和 IEND 也要认出来。校验值对不上要标红，不能装作没看见。
- record.bin：按 README 里那个自定义格式解，每条记录的时间戳、名字、数值都要出来。

两件要当心的事：

一是不能假设文件是好的。我们真实遇到的是文件被截断、魔数写错、长度字段比实际数据还大——
这些情况你得给出明确的报错和已解出来的部分，而不是整个白屏或者卡死。
拖一个不是这两种格式的文件进来，也要好好说"不认识"。

二是大文件。几百兆的日志也可能会拖进来，不能一上来就整个读进内存再渲染，
要能滚、能跳、能只渲染看得见的那一段。

png 的压缩数据不要求你解出像素，只看结构就行。

别引库、别 npm、别构建，原生 ES module。README 里写清楚支持的格式、坏文件怎么处理、大文件怎么处理的。
