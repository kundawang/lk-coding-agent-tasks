我们后台的配置和接口返回越来越复杂，现在靠人肉看 JSON 检查格式，出错都是上线之后才发现。
想让你写个 JSON Schema 校验器（我们自己用，不用做全）。

schema 和两份数据（一份好的、一份故意写坏的）在 samples 里，格式 README 里有，别改。

要支持的关键字我列在 README 里了，重点是这几类：类型、对象（properties/required/additionalProperties）、
数组（items/长度/唯一）、字符串（长度/正则/format）、数字（范围/倍数）、enum/const、
组合（anyOf/oneOf/allOf/not），还有 `#/definitions/xxx` 这种本文件内的 $ref。

两件我特别在意的：

一是报错要指到具体位置。不能只说"校验失败"，要给我 `items[2].price` 这种路径，
让我知道是第几个元素第几个字段出的问题。`oneOf` 失败的时候，把它每个分支为什么失败都列出来——
不然我根本不知道该往哪边改。

二是写得别太慢也别太脆。几百个元素的数组校验不能卡；`$ref` 来回引用（甚至自引用）不能死循环；
schema 本身写错（比如 `type` 写了个不认识的值）要报出来，别默默当通过。

界面就左右两块：左边贴 schema 和数据，右边列问题；点一条问题能定位到对应位置。
数据是通过、还是第几条不合规，要一眼看得见。

别引库、别 npm、别构建，原生 ES module，别去网上拉 schema 标准库。README 里写清楚支持哪些关键字、
$ref 怎么解析、组合关键字失败时错误是怎么组织的。
