我们订单系统的状态老是跟预期对不上，出问题只能翻日志猜。想改成事件溯源那套：
所有状态都由事件算出来，出问题能倒回任意时刻看当时是什么样。

一串事件、两个快照点放在 samples 里（里面故意有重复投递、乱序和非法事件），格式 README 里有，别改。

要做的：按事件重放出订单状态，界面上有时间轴，拖到任意一条事件能看到那一刻的完整状态
（订单、明细、备注、总额）。有快照的话要能用快照加速。

三个重点：

一是状态只能由事件算出来。同一串事件重放两次结果必须一致；有没有快照结果也必须一致——
我要能验证这一点，界面上给个"用不用快照对比一下"的按钮。

二是异常事件要单独列出来，不能悄悄吃掉：同一个 seq 重复投递（只能生效一次）、
seq 比当前小的迟到事件、类型不认识的事件、缺字段的事件，都要在界面上单列一块告诉我，
并且说明是被跳过了还是被插回去重算了。

三是乱序怎么处理要有个说得通的策略（插回去重算，或者明确判冲突），并且写在 README 里。

别引库、别 npm、别构建，原生 ES module。README 里写清楚事件模型、幂等怎么保证、快照与重放怎么对齐。
