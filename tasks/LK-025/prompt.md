我们内网有个文档站，允许同事贴 Markdown。之前有人贴了一段带脚本的内容，差点出事。
想让你自己写个 Markdown 渲染器，把安全这块做扎实。

两份样例在 samples 里：doc.md 是正常文档，evil.md 是各种攻击载荷（我列在 README 里了），别改。

渲染要支持的写法我在 README 里列了：标题、粗斜体、行内码、围栏代码块、有序无序列表（能嵌套）、
引用（能嵌套）、表格、链接图片、分隔线。

解析要你自己写，别引现成的 Markdown 库，也别用 innerHTML 直接塞进去。
我要能选择"输出成安全的 HTML"还是"输出成 DOM 节点"。

安全这块是重点，evil.md 里那些一个都不能漏：脚本标签、事件属性、`javascript:` 链接、iframe、
注释里藏的标签、没闭合的标签、超大嵌套。渲染完必须一个都执行不了，而且页面不能卡死。

链接和图片的地址要按白名单过滤（http/https/mailto），不认识的协议要么去掉链接只留文字，要么明确标出来。

还有：解析失败的输入（没闭合的粗体、乱的表格）不能白屏，要按"能渲染的先渲染出来"的原则继续，
同时告诉我哪一段有问题。

另外给我一个"渲染耗时"和"有多少个节点"的显示，我要贴大文档试试。

别引库、别 npm、别构建，原生 ES module。README 里写清楚语法支持范围、清洗规则、每一类攻击是怎么挡的。
