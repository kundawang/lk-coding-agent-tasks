我们做地图寻路老吵架——有人说 A* 快，有人说 BFS 就够了，谁也没个准数。
想让你做个可视化工具，几种算法摆一起比。

地图样例在 samples/maps.json 里，格式 README 里有，别改。

要实现的算法：BFS、Dijkstra（要支持"难走区域"那种代价）、A*（曼哈顿和八向切比雪夫两种启发都做）、
还有 JPS 跳点搜索（只在没有障碍的图上用）。

要能看到什么：

- 每个算法探索了多少格子、路径多长、路径代价多少、跑了多久
- 探索过程能一步步放出来，能暂停、能单步、能调速度
- 同一张图上四种算法的结果并排看，路径不一样的地方高亮出来

三个我比较在意的点：

- 结果要稳定。同一张图跑两遍，探索的格子数、路径都得完全一样。别因为遍历对象键的顺序变了，
  或者同一批候选格子的排序不稳定，就得出不同结果
- 启发函数的差别要看得出来。曼哈顿和切比雪夫探索的格子形状差挺多，图上要能看出这个差别；
  启发不满足条件的时候（比如带权重的地图用曼哈顿），结果可能不是最优——这种情况要提示我，
  别默默给我一条不是最短的路
- 无解的情况：起点被墙围死、或者目标在墙里，要明确说"到不了"，把探索过的区域画出来给我看

另外地图要能自己画（点格子加墙、拖拽画线）和导入导出 JSON。

别引库、别 npm、别构建，原生 ES module + Canvas。README 里写清楚各算法实现要点、
权重怎么算、无解和"启发不最优"是怎么判断的。
