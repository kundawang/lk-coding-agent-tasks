我们做了个能在本地缓存里跑的页面，但每次发版都出问题：用户手机上还是旧代码，
或者缓存越攒越大，最后有人清不掉只能让他重装。想让你做个调试面板，把这事看清楚。

缓存策略配置在 samples/policy.json，格式 README 里有，别改。

页面本身很简单（几张图、一个请求接口的按钮），重点是旁边那个调试面板，要能看到：

- 当前 Service Worker 是安装中、已激活还是等待中，当前缓存版本是哪个
- 缓存里有多少条、多大，能按 URL 列出来、能单条删、能整体清
- 每次请求的命中情况：命中缓存 / 走了网络 / 超时回落，实时列出来
- 点"检查更新"能看到有没有新版本，新版本在 waiting 的时候要提示我

两个重点：

一是升级要干净。版本号改成 v4 之后，旧缓存必须清掉，不能越攒越多；升级过程中页面不能白屏。

二是超时回落要真的生效。按策略里配的 timeoutMs，网络慢的时候要按时回落，
不能一直等在那儿。断网刷新之后 precache 里那些要真的能打开。

调试面板本身别被缓存住，不然它显示的就是旧状态了。

别引库、别 npm、别构建，原生 ES module。README 里写清楚各策略的行为、缓存版本怎么管、面板怎么保证不被缓存。
