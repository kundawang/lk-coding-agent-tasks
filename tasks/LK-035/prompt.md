我们内部文档散在几十个 md 文件里，用编辑器自带的搜索找东西特别难——搜"缓存"能出来一堆，
但哪篇最相关看不出来。想让你做个本地的搜索工具。

文档和一组查询放在 samples 里，格式 README 里有，别改。

要做的：给这些文档建索引，然后像搜索引擎那样查。查询要支持单词、多个词（都要有）、
引号里的短语、前缀匹配（超时*）、还有排除词（部署 -回滚）。

结果要按相关度排，相关度一样的按文件名稳定排；每条结果显示文档名、命中的片段、
片段里把命中的词标出来。点一下能看全文。

另外：中文要能搜——按字符二元组切就行，别引入分词库。

两条我比较在意：

一是相关度要说得清楚。用 tf-idf 还是 BM25 都行，但得写在 README 里，而且同一份数据查两次结果必须一样。

二是要能增量。改一篇文档只重建它那部分，界面上要有"这次更新了几个词条"这种反馈。
我不接受改一个字就全量重建——文档多起来会等死人。

查询里带正则特殊字符、空查询、只有排除词，都不能崩，要有说得通的输出。

别引库、别 npm、别构建，原生 ES module。README 里写清楚索引结构、相关度公式、增量更新的范围。
